# 精选短文统一模型调用层

> 路径约定：本文命令均在项目根目录执行；主页面、词库和 `.env` 仍在根目录，现行说明位于 `docs/`。目录调整不改变业务规则、第三方许可或材料上传白名单。


## 当前范围

`server/reading-models.cjs` 提供 DeepSeek 的统一服务端调用接口，由 `modules/reading/reading-generate.cjs` 用于阅读生成、`modules/translation/translation-service.cjs` 用于独立翻译。打开精选短文、换文、查看翻译历史或保存候选词不会调用 API；只有明确提交阅读生成或翻译并确认费用时，才可能发起真实调用。翻译不调用 Tavily，也不套用阅读资格规则。

生成流程可显式传入 `provider` 和 `model`；下面的路径以项目根目录中的调用脚本为例，模块内的相对引用须按该模块位置调整：

```js
const {createModelClient} = require('./server/reading-models.cjs');
const client = createModelClient();

const result = await client.generate({
    provider: 'deepseek', // 仅支持 DeepSeek
    model: 'deepseek-flash',
    instructions: '生成符合要求的阅读材料草稿。',
    input: JSON.stringify(sharedSearchBundle),
    schema: readingDraftSchema,
    maxOutputTokens: 6000
});
```

## 本地配置

1. 复制项目根目录的 `.env.example` 为同目录的 `.env`，不要放入 `server/` 或 `docs/`。
2. 只在本机 `.env` 中填写 DeepSeek 密钥：

```dotenv
DEEPSEEK_API_KEY=
```

3. 密钥为空时，生成和翻译入口会明确显示尚未配置。阅读另需 Tavily 密钥及 `READING_ALLOW_EXTERNAL_CALLS=true`；翻译只需 `TRANSLATION_ALLOW_EXTERNAL_CALLS=true`。两项开关默认关闭，改后重启。
4. `.env` 和 `.model-usage.jsonl` 已列入 `.gitignore`。不要把真实密钥写入 HTML、Markdown、截图、聊天或任何受版本管理的文件。
5. 修改模型允许列表时，用英文逗号分隔，并保证默认模型包含在列表中：

```dotenv
DEEPSEEK_MODELS=deepseek-flash,deepseek-v4-pro
DEEPSEEK_DEFAULT_MODEL=deepseek-flash
```

服务只对外提供 `configured`、默认模型和允许模型，不返回密钥。官方 API 地址固定在服务端代码中，避免页面或材料文件改变密钥发送目标。

## 接口适配

### DeepSeek

- 调用 `POST https://api.deepseek.com/chat/completions`。
- 使用 `response_format: {"type":"json_object"}`，并在 system 消息中明确要求 JSON、提供 schema。
- 当前实现关闭 thinking mode，并通过 `max_tokens` 限制单次输出。
- JSON Output 不能代替字段校验，因此响应解析后必须执行本地 schema 校验。

官方参考：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

## 统一返回结构

DeepSeek 成功时返回：

```json
{
  "provider": "deepseek",
  "model": "deepseek-flash",
  "requestId": "供应商请求 ID 或 null",
  "output": {"模型生成的结构化对象": true},
  "usage": {
    "inputTokens": 0,
    "cachedInputTokens": 0,
    "outputTokens": 0,
    "reasoningTokens": 0,
    "totalTokens": 0
  },
  "finishReason": "stop",
  "attempts": 1,
  "durationMs": 0
}
```

返回值和本地用量日志均不包含 API 密钥、输入提示或模型原始响应。

## 超时、重试和限制

- 默认每次尝试超时 45 秒，可配置范围为 1–300 秒。
- 默认最多重试 2 次，即最多 3 次请求；上限固定为 3 次重试。
- 上述自动重试用于阅读模型层；翻译业务显式覆盖为 0，失败及未完成阶段仅由用户确认后手动重试，避免重复收费。
- 只重试超时、网络错误、HTTP 408/409/429/5xx、无效 JSON、响应结构错误或本地 schema 不匹配。
- 401/403、普通 4xx、输出达到 token 上限等不会盲目重试。
- 所有重试仍使用用户明确选择的同一供应商和模型，绝不自动切换供应商。
- `MODEL_MAX_OUTPUT_TOKENS` 默认 6000、代码硬上限 20000；单次调用请求更大值时会被本地配置上限截断。
- 响应正文另有 4 MiB 上限。

## 用量记录

默认把脱敏后的成功调用记录追加到 `.model-usage.jsonl`，只包含时间、供应商、模型、请求 ID、尝试次数、耗时和 token 用量。设置 `MODEL_USAGE_FILE=off` 可关闭；自定义路径必须仍位于项目目录内。

模型层记录令牌用量；生成编排层另以带核对日期的价格快照计算估算金额。估算字段明确标为 `estimate`，实际金额恒记为 `null`，最终以供应商账单为准。

## 离线验证

`node tests/check-reading-models.cjs` 使用模拟 HTTP 响应检查：

- DeepSeek 成功响应及参数检查；
- 统一输出和 token 用量；
- API 密钥不出现在公开配置或用量日志；
- 单次输出上限；
- 超时、429 和格式异常的有限重试；
- DeepSeek 输出的本地 JSON Schema 校验；
- 失败后不自动切换供应商。

这些测试不会连接 DeepSeek 或任何搜索服务。
